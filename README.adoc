= Posix
:toc:
:sectnums:
:lang: en-GB
:source-highlighter: rouge

OpenHFT Posix exposes a subset of native file, memory, clock and affinity
operations. The core library compiles and runs on Java 8. Native pointers
remain the caller's responsibility; this is not a memory-safe sandbox.

== Providers

[cols="1,2,3",options="header"]
|===
| Selection | Provider | Availability
| auto / jnr | JNRPosixAPI or WinJNRPosixAPI | Unix or Windows native calls; auto may fall back to NoOp on load failure.
| jna | WinJNAPosixAPI | Windows x64 JNA interface mappings.
| jna-direct | WinJNADirectPosixAPI | Windows x64 JNA direct mappings.
| ffm | WinFFMPosixAPI | Windows x64, optional posix-ffm artifact, Java 22+.
| noop | NoOpPosixAPI | Explicitly disabled native provider.
|===

Use `-Dchronicle.posix.provider=jna` (or another selection above). Explicit
requests fail clearly if unavailable; they do not silently select NoOp.
The old abstract JNAPosixAPI and RawPosixAPI classes are not complete providers.
FFM uses final APIs, not Java 21 preview features. See
link:posix-ffm/README.adoc[FFM build and deployment instructions].

== Windows contracts

See link:src/main/docs/windows-capabilities.adoc[the supported subset and
unavailable modes]. JNR, JNA interface/direct and FFM use common Windows
semantics and the same contract tests, including all 43 public signatures.

Supported operations include binary/Unicode file I/O, 64-bit seek/truncate,
mode-zero file allocation, shared/private file mappings, synchronous flush,
selected clocks, positive-length byte-range locks and single-group affinity.
Unavailable modes return documented failures; the legacy void mlockall is
explicitly an unavailable no-op. Windows mandatory locks differ from POSIX
advisory locks. Disk usage returns allocated KiB.

Native failure usually returns -1 (false for page locking); inspect
`lastError()` / `lastErrorStr()`. Invalid/unsupported clock IDs throw
IllegalArgumentException. See individual provider contracts for exceptions.

== Build and tests

With JDK 8 or a supported later JDK:

[source,shell]
----
mvn -B clean verify
----

The optional FFM artifact is a separate build and does not participate in
the default Java 8 build. To build it, first install the core, then select
JDK 22+ and run:

[source,shell]
----
mvn -B -f posix-ffm/pom.xml clean verify
----

The optional `quality` profile runs the shared Checkstyle/SpotBugs rules
and requires access to the configured chronicle-quality-rules artifact.
Normal verify does not imply this optional profile passed.

== Performance and qualification

Zero allocation is a design objective, not a guarantee for all bindings.
See link:src/main/docs/windows-qualification.adoc[local qualification and
exploratory JMH results]. JNA interface/direct, JNR and FFM have different
dispatch/allocation costs. JNR remains the default; FFM is opt-in.

The Windows CI matrix covers Java 8, 11, 17, 21 and 25 for the core, plus
22/25 for FFM. Linux/macOS regression jobs cover shared changes. Only report
a platform as qualified after the corresponding results pass.
