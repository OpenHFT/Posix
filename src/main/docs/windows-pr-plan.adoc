== Outcome and status

Implementation update (FIX-292, 14 November 2026): the plan below is the
original breakdown. Work has been consolidated into six stacked PRs:
https://github.com/OpenHFT/Posix/pull/93[file I/O],
https://github.com/OpenHFT/Posix/pull/94[shared contracts and JNA],
https://github.com/OpenHFT/Posix/pull/95[mappings and page operations],
https://github.com/OpenHFT/Posix/pull/96[allocation, locks and affinity],
https://github.com/OpenHFT/Posix/pull/97[optional FFM], and the qualification
branch (CI, JNA direct mapping, benchmarks and documentation).
See link:windows-qualification.adoc[current validation and remaining limits].

Every one of the 43 declared `PosixAPI` signatures, including static methods
and default overloads, must have an explicit behavioural test. Every Windows
operation must either work for a documented subset or explicitly report that
it is unavailable. Unsupported behaviour is tested, not skipped.

The shared contract now executes all 43 signatures for each Windows binding.
This does not mean every edge case below has been qualified. See
link:windows-support.adoc[observations and remaining defects].

The Java 8 compilation requirement is mandatory. The agreed provider design
is documented in link:native-provider-strategy.adoc[native provider strategy]:
retain JNR, implement JNA parity, and build Panama in a separate optional
Java 22+ artifact. The original series gains PRs 2a and 2b below.

PRs 5 and 8's pure helper tests can progress independently of file mappings.
Do not delay truthful unsupported-operation results until native replacements
are ready. Each later implementation replaces its unsupported-contract test
with success/error tests for the supported subset and retains rejection tests.

== Unavailable-operation contract (PR 2)

* Integer status/count and address-returning system calls return `-1` and
set a documented thread-local errno for unsupported operations. Use a
verified Windows CRT ENOSYS value; do not copy Linux errno numbers.
`mmap` must never return zero as pretend success.
* Boolean locking calls return `false` with the same documented error.
* Invalid/unsupported clock IDs throw `IllegalArgumentException`, matching
the current interface contract; include the clock ID in the message.
* `du` throws an informative `IOException` until native support exists.
* `mlockall` has an existing documented no-op default and no return value.
Prefer an explicit Windows override throwing `UnsupportedOperationException`,
but audit Chronicle callers and ship a compatibility note with this change.
Do not change other providers' defaults incidentally. If compatibility
requires retaining the no-op temporarily, mark it unavailable in the
capability table and test the documented no-op explicitly.
* Distinguish invalid argument, access denied, invalid descriptor, unsupported
feature and exhausted resources. Map Win32 errors to the same errno domain
as CRT operations; test thread isolation and error freshness.

== Test architecture and completion gates

* Pure contract tests cover every default overload, flag translation,
overflow, masks and native failure path through an injectable boundary.
Do not count mere forwarding as sufficient coverage of native semantics.
* Native Windows tests verify contents, positions, clocks and OS effects.
They must assert the selected provider is real, not a fallback NoOp.
Unsupported operations get assertions on results/errors, not assumptions.
* Unsafe protection/unmap tests, blocking locks and provider global state
run in bounded child JVMs. Parent tests enforce timeouts, record exit codes
and restore resources. Do not intentionally dereference invalid pointers in
the main Surefire JVM.
* Each implementation PR updates the capability matrix, Javadocs and tests
together. List not-available modes and minimum OS/filesystem requirements.
* Every PR runs clean verify; quality checks require resolving
`net.openhft:chronicle-quality-rules:1.27.0-SNAPSHOT`, currently unavailable
to the local quality build. Do not silently disable that gate.
* Run the base build/tests with actual JDK 8, not just target 8 on a newer
compiler. Run every contract against each advertised JNA/JNR/FFM provider;
FFM alone has a Java 22+ build and execution baseline.
* PR 9 is complete only when the registry matches all 43 current signatures
and Windows reports show their tests executed. Add failure-path assertions
and selective mutation checks to ensure tests detect no-op success stubs.
