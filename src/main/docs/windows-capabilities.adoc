= Windows Provider Capabilities (FIX-292)
:toc:
:sectnums:

== Selection and requirements

Windows providers require a 64-bit Windows JVM. The Java 8 core supplies JNR
(automatic selection) and JNA. Set `chronicle.posix.provider` to `jnr`, `jna`, `jna-direct`,
`noop` or `ffm` to request a provider. Explicit requests never silently fall
back. FFM requires Java 22+ and a separately built optional artifact.
JNA interface and direct mapping are both available; no blanket zero-allocation
claim is made. See windows-qualification.adoc for measured allocation rates.

== Implemented contracts

* Binary open/read/write/close, UTF-16 paths, 64-bit seek and truncate.
* Open flags: read, write, read/write, append, create, truncate, exclusive.
Unsupported bits return EINVAL. Permission read/write bits map to CRT modes;
POSIX ownership and ACL semantics are not provided.
* Seek SET/CUR/END. DATA/HOLE are unavailable. The previously incorrect
WhenceFlag constants are corrected to native POSIX values; code persisting
the old numeric enum values must migrate.
* CRT errno and error strings, off-heap allocation/free, PID/native TID,
active and maximum Windows logical processor counts across groups.
* Realtime, monotonic, process CPU and thread CPU clocks. Other clock IDs
throw IllegalArgumentException. Timeval is two 64-bit fields on this provider.
* File-backed shared and private/copy-on-write mappings, read or read/write
protection, allocation-granularity-aligned offsets and complete-view unmap.
Mappings must fit inside the existing file. Address hints/fixed mappings,
anonymous mappings, other protection modes and partial unmaps are unavailable.
* MS_SYNC flushes the view and, for writable shared views, its duplicated file
handle. Closing the original descriptor does not invalidate the view. MS_ASYNC
and MS_INVALIDATE are unavailable. Callers must unmap every successful view.
* MADV_WILLNEED uses PrefetchVirtualMemory where exported by Windows (8+).
Other advice modes are unavailable. VirtualLock supports mlock and
mlock2(false), subject to OS quotas. Unmapping releases locked mapped pages;
the public API has no munlock operation. mlock2(true) is unavailable.

== Unavailable contracts

Mode-zero fallocate reserves allocation and extends EOF without changing
the file position; other modes (punch-hole, keep-size, etc.) are unavailable.
Callers must serialise operations that concurrently resize the same file.
Disk usage supports individual files and returns allocated KiB, preserving
the facade's historical du convention; it does not recursively count directories.

Byte-range locking supports F_LOCK/F_TLOCK/F_ULOCK for positive lengths
relative to the current offset. Windows locks are mandatory for ordinary
file I/O, unlike POSIX advisory locks. F_TEST, backwards ranges and zero-length
to-EOF locking are unavailable. Cross-process contention is tested in bounded
child JVMs.

Affinity accepts zero for the current thread or a native thread ID. It
supports a single processor group (up to 64 configured logical CPUs), rejects
other topologies with ENOSYS, and does not treat the argument as a process ID.
The integration test changes only a worker thread and restores its mask.

Unsupported modes report -1 with CRT ENOSYS (40). The void
mlockall method retains its historical no-op for compatibility
and sets ENOSYS: it does not lock pages. Disk usage errors throw IOException.

== Test obligations

WindowsContractTest runs the same assertions against each advertised binding.
An invocation registry requires every one of the 43 PosixAPI signatures to
execute, including overloads, static selection and unavailable calls.
WindowsBoundaryTest checks large transfer capping without huge allocation
and affinity masks across CPU indexes 31/32/63/64/128 with buffer canaries.
Raw pointer validity remains the caller's responsibility.
